1 · What is an AI Language Model (LLM)?

Before understanding TruthGuard AI, you need to understand what an LLM (Large Language Model) is — because it is the brain at the center of everything.

1.1 The Simple Explanation

Imagine you read every book, article, website, forum post, and scientific paper ever written — about 500 billion pages of text. After reading all of that, you develop an incredibly powerful intuition for how language works, how facts connect, how to explain things, and how to write convincingly about nearly any topic.

An LLM is a computer program that has essentially done that — except it didn't "read" and "remember" like a human. Instead, it was trained by a mathematical process that compressed all that text into billions of numerical weights (parameters) stored inside the model.

Analogy — The Expert Guesser

Think of an LLM like a musician who has listened to millions of songs. Ask them to continue a melody and they'll produce something that sounds very musical and correct — because they've absorbed patterns from millions of examples. They're not looking anything up; they're generating based on deeply learned patterns. LLMs do the same thing with text.

1.2 How LLMs Actually Work — Token by Token

An LLM doesn't think in words or sentences. It works in tokens — small chunks of text (roughly 1 word = 1–2 tokens). Given a sequence of tokens, the model predicts: "what token is most likely to come next?"

Example: You give it the tokens "The Stripe API uses" and it predicts "authentication" as the most likely next token, then "via", then "API", then "keys", and so on — until it forms a complete answer.

This might sound simple, but when you do this billions of times across hundreds of billions of training examples, something remarkable emerges: the model learns facts, reasoning, coding, translation, summarisation, and much more — all from the single task of "predict the next token."

1.3 Gemini — The LLM Used in This Project

TruthGuard AI uses Gemini — Google's family of LLMs. Specifically it auto-discovers and uses the best available model from your API key, with preference for Gemini 2.5 Flash.

ModelStrengthUsed For
Gemini 2.5 FlashFast, smart, great at structured outputAnswer generation, fact checking, consistency grading
Gemini Embedding 001Converts text to numbers (vectors)Embedding document chunks and user queries

Gemini is accessed via Google's Generative Language REST API at generativelanguage.googleapis.com. This project calls it directly using Python's requests library — sending JSON over HTTPS and receiving JSON back.

2 · The Hallucination Problem — Why AI Lies

2.1 What is Hallucination?

Here is the most important thing to understand about LLMs: they don't look things up — they generate. There is no encyclopedia inside the model. When you ask a question, the model produces text that statistically resembles a correct answer, based on patterns in its training data.

This works brilliantly most of the time. But it also means the model can generate text that sounds absolutely confident and authoritative — while being completely wrong. AI researchers call this hallucination.

Analogy — The Confident Bluffer

Imagine a contestant on a quiz show who, instead of saying "I don't know," always gives an extremely confident, detailed, plausible-sounding answer — even when they have no idea. They've absorbed so much general knowledge that they can construct convincing-sounding answers about nearly anything. Most of the time they're right. But sometimes they fabricate details with total confidence. That's an LLM hallucinating.

2.2 Real Examples of Hallucination

❌ Hallucinated Answer

Q: What is the Stripe webhook retry policy?

"Stripe retries webhooks up to 5 times over 24 hours using an exponential backoff of 30 minutes between attempts."

⚠ The numbers here were fabricated. Stripe actually retries over several days with different intervals.

✅ Grounded Answer (RAG)

Q: What is the Stripe webhook retry policy?

"According to the Stripe documentation at stripe.com/docs/webhooks, Stripe attempts delivery multiple times over several days..."

✓ Answer derived strictly from retrieved documentation chunks.

2.3 Why This Matters for Stripe Documentation

If someone is building a payment system and gets incorrect API parameters, endpoint names, or webhook behaviour from an AI assistant, it could cause real financial or technical damage. TruthGuard AI treats hallucination as a first-class problem: it not only tries to prevent it (via RAG), but also detects and scores it in every answer it gives.

3 · What are Embeddings?

This is one of the most important concepts to understand, because it underpins the entire retrieval system. Embeddings are how computers understand meaning.

3.1 The Core Idea — Turning Words into Numbers

Computers can only process numbers, not words. An embedding is a way to convert a piece of text into a list of numbers (called a vector) that captures the meaning of that text.

In TruthGuard AI, we use Gemini Embedding 001, which converts any text into a list of 3,072 numbers. This list of 3,072 numbers is the embedding — a mathematical representation of what that text means.

Analogy — GPS Coordinates for Meaning

Think of GPS coordinates. London is at (51.5°N, 0.1°W). Paris is at (48.8°N, 2.3°E). They're different places, but their coordinates are close — because geographically, they're close. Berlin (52.5°N, 13.4°E) is close to both. Sydney (33.8°S, 151.2°E) is far away from all three.

Embeddings do the same thing for meaning. Texts with similar meaning get similar coordinates (numbers). "How do I accept a payment?" and "How do I charge a customer?" will produce very similar vectors. "What is the weather today?" will produce a very different vector.

3.2 Semantic Similarity — Why This is Magical

The revolutionary thing about embeddings is that they capture semantic similarity — similarity in meaning — not just similarity in exact words. Consider these two sentences:

  • "How do I create a PaymentIntent?"
  • "What's the process for initializing a payment in Stripe?"

These sentences share only the word "a" and "Stripe" — yet their embeddings will be very close numerically because they mean the same thing. This allows TruthGuard AI to find relevant documentation even when the user's question uses completely different words from the documentation.

3.3 How Similarity is Measured — Cosine Distance

To compare two embeddings (two lists of 3,072 numbers), we use cosine similarity. This measures the angle between the two vectors in a 3,072-dimensional mathematical space.

  • Cosine similarity of 1.0 = identical meaning (same vector direction)
  • Cosine similarity of 0.9 = very similar meaning
  • Cosine similarity of 0.5 = loosely related
  • Cosine similarity of 0.0 = unrelated
Analogy — The Compass Direction

Imagine each text is an arrow pointing in a direction in 3D space. "I love dogs" might point North-East. "I adore puppies" also points North-East (very similar direction → high cosine similarity). "The stock market fell today" points South-West (very different direction → low cosine similarity). The angle between the arrows is what cosine similarity measures.

3.4 How This Project Uses Embeddings

Embeddings are used in two places:

1
During ingestion (one-time setup) Every 500-character chunk of Stripe documentation is converted to a 3,072-number embedding and stored in Pinecone. We're essentially saying: "here is the mathematical fingerprint of this chunk's meaning."
2
During query (every question asked) The user's question is also converted to an embedding. We then find the 5 doc chunks whose embeddings are most similar (closest cosine distance) to the question's embedding. Those are the most relevant chunks to answer the question.

The REST API call to get an embedding looks like this:

POST https://generativelanguage.googleapis.com/v1beta/models/gemini-embedding-001:embedContent
     ?key=YOUR_API_KEY

Body:
{
  "content": {
    "parts": [{ "text": "How do I create a PaymentIntent?" }]
  }
}

Response:
{
  "embedding": {
    "values": [0.0234, -0.0156, 0.0891, ..., 0.0421]  ← 3,072 numbers
  }
}

4 · What is a Vector Database? (Pinecone)

4.1 The Problem It Solves

After generating embeddings for thousands of document chunks, we need to store them and search through them quickly. A regular database (like MySQL or PostgreSQL) is great at exact lookups — "find all rows where name = 'John'". But it cannot answer: "find me the 5 embeddings most similar to this query embedding" efficiently.

A vector database is a specialised database designed exactly for this task: storing high-dimensional vectors and performing fast similarity searches across them.

Analogy — The Music Recommendation Engine

Imagine Spotify stores every song as a list of numbers describing its musical characteristics (tempo, key, energy, danceability, etc.). When you hit "find songs like this," Spotify doesn't compare your song to every song in its library one by one — it uses a specialised index that can find the closest matches in milliseconds across 100 million songs. A vector database is that specialised index, but for any kind of meaning, not just music.

4.2 Pinecone — The Specific Tool Used

Pinecone is a cloud-hosted vector database. This project uses its Serverless tier (free). Here's what it stores for TruthGuard AI:

4.3 The Query Operation

When a user asks a question, TruthGuard AI sends this to Pinecone:

# Python code in rag/retriever.py
results = index.query(
    vector=query_embedding,   # the 3,072-number embedding of the question
    top_k=5,                  # return the 5 most similar chunks
    include_metadata=True     # include url, title, text alongside each result
)

Pinecone responds in milliseconds with the 5 most semantically relevant documentation chunks — even though it may be searching through thousands of stored vectors.

5 · What is RAG? (Retrieval-Augmented Generation)

5.1 The Core Concept

RAG (Retrieval-Augmented Generation) is a technique that gives an LLM access to a specific knowledge base at query time — solving the hallucination problem by grounding the model's answer in real, retrieved documents rather than training-data memory.

The name tells you exactly what it does:

  • Retrieval — find relevant documents from a knowledge base
  • Augmented — add them to the LLM's prompt as context
  • Generation — let the LLM generate an answer from that context
Analogy — The Open Book Exam

Without RAG, asking an LLM a question is like asking a student to take a closed-book exam. They answer from memory — mostly right, but prone to errors and fabrications.

RAG is like giving the student specific relevant book pages to read right before answering. The student still writes the answer in their own words — but it's now grounded in the actual source material sitting in front of them. If they say something not in those pages, they're going off-script.

5.2 How RAG Works in TruthGuard AI

1
User asks: "How do I verify Stripe webhooks?"
2
Embed the question: Convert to a 3,072-number vector using Gemini Embedding.
3
Search Pinecone: Find the 5 document chunks from Stripe docs most similar to the question vector.
4
Build the prompt: Inject those 5 chunks into the LLM prompt as "context". Instruct the LLM: "Answer ONLY from this context."
5
Generate: Gemini reads the injected context and writes an answer grounded in the actual Stripe documentation.

5.3 Why RAG is Better Than Fine-Tuning

An alternative to RAG is fine-tuning — training the LLM on Stripe documentation so it "memorises" it. RAG is better for this use case because:

RAGFine-Tuning
CostFree (just storage + embedding API calls)Very expensive (GPU training time)
UpdatesJust re-scrape and re-embedRe-train the entire model
CitationsBuilt-in (we know which chunk was used)No source tracking
Scope controlEasy (only Stripe docs in the vector DB)Hard (model absorbs general knowledge too)

6 · What is LangChain?

6.1 The Problem It Solves

Building an AI application involves many repetitive tasks: formatting prompts, calling models, parsing outputs, chaining steps together. LangChain is a Python framework that provides standardised building blocks for all of this.

Think of it like React for web development — you could write raw JavaScript, but React gives you reusable components (buttons, forms, etc.) that save time and work consistently. LangChain gives you reusable AI components.

6.2 What TruthGuard AI Uses from LangChain

This project uses LangChain primarily for prompt templates — reusable prompt structures with variable placeholders:

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a Stripe documentation expert. Answer ONLY from context."),
    ("human",  "Context:\n{context}\n\nQuestion: {query}")
])

# Fill in the variables:
filled_prompt = prompt.format_messages(
    context="[retrieved doc chunks]",
    query="How do I verify webhooks?"
)

LangChain also underpins LangGraph (the pipeline framework), so it's a transitive dependency throughout the project.

7 · What is LangGraph?

7.1 Why LangGraph — Not Just a Chain

LangChain's basic abstraction is a "chain" — a linear sequence: step A → step B → step C. For simple pipelines this is fine. But TruthGuard AI needs something more sophisticated: a pipeline with multiple independent agents, shared state, and the potential for conditional logic and loops.

LangGraph models your pipeline as a directed graph — a network of nodes (processing steps) connected by edges (data flow). This makes complex multi-agent systems much easier to build and reason about.

Analogy — Factory Assembly Line

Think of a car factory. A car starts as raw materials and passes through stations: welding → painting → engine fitting → quality control → final inspection. Each station does one specific job and passes the result to the next. LangGraph is the conveyor belt system that manages this flow — each "station" is a node, and the car (your data) passes through with accumulated work attached to it at each stage.

7.2 Key LangGraph Concepts

StateGraph

The main class. You define a TypedDict that describes all the data the pipeline will carry, then register nodes and edges.

State

A shared Python dictionary that flows through every node. Each node reads from it and writes updates back to it. In TruthGuard AI, the state carries: the original query, retrieved context, the generated answer, fact-check results, and consistency scores — all accumulated as data moves through the graph.

Nodes

Python functions that take the current state, do something (call an API, run a model, parse output), and return a dictionary of updated state keys.

Edges

Connections between nodes. add_edge("A", "B") means: after node A finishes, run node B. LangGraph supports conditional edges too (e.g., "if score > 50, go to node X, else go to node Y").

# How the TruthGuard pipeline is wired in graph/pipeline.py:

graph = StateGraph(PipelineState)
graph.add_node("retrieve",          retrieve_node)
graph.add_node("generate",          generate_node)
graph.add_node("fact_check",        fact_check_node)
graph.add_node("consistency_guard", consistency_guard_node)
graph.add_node("compile",           compile_node)

graph.set_entry_point("retrieve")
graph.add_edge("retrieve",          "generate")
graph.add_edge("generate",          "fact_check")
graph.add_edge("fact_check",        "consistency_guard")
graph.add_edge("consistency_guard", "compile")
graph.add_edge("compile",           END)

pipeline = graph.compile()
result = pipeline.invoke({"query": "How do webhooks work?", ...})

8 · What are AI Agents?

8.1 Agent vs. Simple LLM Call

A simple LLM call is: give the model a prompt, get text back. An AI agent is a more sophisticated pattern where:

  • The LLM is given a specific role and goal
  • It receives structured inputs relevant to that role
  • It is expected to produce structured output (often JSON)
  • Its output is used programmatically by the next step
Analogy — A Company Department

Think of a company with departments. You don't ask the entire company a question — you route it to the right department. The Legal department has a specific mandate, receives specific inputs (contracts, complaints), and produces specific outputs (legal opinions, risk assessments). A software developer department does the same with code.

In TruthGuard AI, the Fact Checker agent is like the Legal department: it has one specific job (verify claims), receives structured inputs (answer + context), and returns structured verdicts. The Consistency Guard is a separate department that performs an independent audit.

8.2 How Agents Are Implemented Here

In TruthGuard AI, each agent is a Python function that:

  1. Constructs a carefully engineered prompt with a specific role description and exact output format specification
  2. Calls the Gemini LLM via REST at temperature 0 (maximum determinism)
  3. Parses the JSON response from the LLM
  4. Returns a Python dictionary

The key to making agents work reliably is the output format specification in the prompt. The model is told exactly what JSON to return, shown an example template, and instructed: "Return ONLY this JSON — no markdown, no extra text."

10 · The 5-Node Pipeline — Step by Step

Node 1 — RETRIEVE (rag/retriever.py)

What it receives: the user's raw question (a string)

What it does:

1
Calls the Gemini Embedding REST API with the question text and task type RETRIEVAL_QUERY. Gets back 3,072 numbers.
2
Sends those 3,072 numbers to Pinecone asking for top_k=5 — the 5 most similar vectors. Pinecone returns 5 document chunks with their metadata (url, title, text) and similarity scores.
3
Formats the chunks into a context string with source headers, and extracts a deduplicated list of source URLs. Writes both to the shared LangGraph state.

What it writes to state: context (formatted text), sources (list of URLs)

Node 2 — GENERATE (rag/generator.py)

What it receives: context and query from state

What it does: Builds a two-part prompt:

SYSTEM: "You are TruthGuard AI. Answer ONLY from the provided context.
        Never use general knowledge. Never fabricate API details."

USER:   "Context from Stripe documentation:
        [the 5 retrieved chunks go here]

        Question: [user's question]

        Answer strictly from the context above:"

Sends this to Gemini at temperature=0.1 (near-deterministic but slight variation allowed). Gets back the answer text.

What it writes to state: answer

Node 3 — FACT CHECK (agents/fact_checker.py)

What it receives: answer and context from state

What it does: Sends a carefully crafted prompt to Gemini at temperature=0 instructing it to act as a fact-checking agent:

  1. Extract every atomic factual claim from the answer
  2. For each claim, check whether it is SUPPORTED, UNSUPPORTED, or CONTRADICTED by the context
  3. Return a JSON object with all verdicts and an overall PASS/FAIL

Example output from this node:

{
  "claims": [
    {
      "claim": "Stripe sends a Stripe-Signature header with each webhook",
      "verdict": "SUPPORTED",
      "reason": "Context explicitly mentions Stripe-Signature header in webhook verification."
    },
    {
      "claim": "Webhook events expire after 72 hours",
      "verdict": "UNSUPPORTED",
      "reason": "No expiry timing mentioned in the retrieved context."
    }
  ],
  "overall_verdict": "FAIL",
  "summary": "One of two claims lacks documentation support."
}

What it writes to state: fact_check_result

Node 4 — CONSISTENCY GUARD (agents/consistency_guard.py)

What it receives: query, answer, fact_check_result, context from state

What it does: A second independent Gemini call at temperature=0. This agent performs a holistic audit — it reads everything and assigns a numerical risk score:

ScoreLabelColour in UIWhat it means
0 – 20TRUSTEDGreenAll claims supported, answer is accurate and appropriately scoped
21 – 50SUSPICIOUSAmberSome unsupported claims; use with caution
51 – 100HALLUCINATEDRedSignificant fabrications or contradictions detected

Example output:

{
  "hallucination_score": 22,
  "label": "SUSPICIOUS",
  "final_summary": "The answer accurately describes webhook verification but includes one timing claim not found in the retrieved documentation. Use the verified portion with confidence.",
  "additional_flags": ["unverified_expiry_timing"]
}

What it writes to state: consistency_result

Node 5 — COMPILE (graph/pipeline.py)

What it does: Assembles answer, sources, fact_check_result, and consistency_result into a single final_output dictionary that the FastAPI endpoint returns as JSON.

11 · Hallucination Detection — The Two-Layer System

11.1 Why Two Agents Are Better Than One

A single agent verifying its own output is unreliable — the same model that generated a hallucination may validate it too. Two independent agents with different scopes provide defence in depth:

AgentScopeOutputCatches
Layer 1 — Fact Checker Fine-grained: claim by claim Per-claim verdicts + PASS/FAIL Individual wrong facts, fabricated details, contradictions
Layer 2 — Consistency Guard Holistic: the whole answer Score 0–100 + TRUSTED/SUSPICIOUS/HALLUCINATED Misleading framing, selective omission, overconfident tone, scope violations

11.2 How Claim Extraction Works

The Layer 1 agent breaks an answer into its atomic facts. The sentence:

"You can set up webhooks in the Stripe Dashboard by going to Developers → Webhooks, where you can add an endpoint URL that receives events like payment_intent.succeeded."

…would be decomposed into these individual claims, each verified separately:

  1. Webhooks are configured in the Stripe Dashboard
  2. The path is Developers → Webhooks
  3. You can add an endpoint URL
  4. The endpoint receives events like payment_intent.succeeded

Why this matters: a single unsupported fact buried in an otherwise correct answer would be missed if you only verified the answer as a whole. The atomic approach catches everything.

11.3 The JSON Output Contract

Both agents are instructed with extreme precision about their output format. Here is the exact instruction given to the Fact Checker:

"Return ONLY a valid JSON object — no markdown fences, no extra text:
{
  "claims": [
    {
      "claim": "<exact claim text from the answer>",
      "verdict": "SUPPORTED|UNSUPPORTED|CONTRADICTED",
      "reason": "<one sentence citing specific context evidence>"
    }
  ],
  "overall_verdict": "PASS|FAIL",
  "summary": "<two-sentence overall assessment>"
}"

Temperature is set to 0 for both agents — the lowest possible setting — to maximise consistency and minimise creative variation in the verdicts.

11.4 Robust JSON Parsing

Despite the strict instruction, LLMs occasionally add markdown formatting (```json fences). The parsing function applies three-stage recovery:

def _parse_json(raw: str) -> dict:
    # Stage 1: strip markdown fences if present
    raw = re.sub(r"^```(?:json)?", "", raw).rstrip("`").strip()

    # Stage 2: direct parse
    try:
        return json.loads(raw)
    except json.JSONDecodeError:
        pass

    # Stage 3: find first {...} block via regex and parse that
    match = re.search(r"\{.*\}", raw, re.DOTALL)
    if match:
        try:
            return json.loads(match.group())
        except:
            pass

    # Stage 4: safe fallback — never crash the pipeline
    return {"claims": [], "overall_verdict": "FAIL",
            "summary": f"Parse failed. Raw: {raw[:300]}"}

12 · The Complete Tech Stack Explained

FastAPI

FastAPI is a modern Python web framework for building APIs. It handles incoming HTTP requests from the browser, validates the request body, calls the pipeline, and returns the JSON response. It's used because it's fast (asynchronous), type-safe (uses Python type hints), and auto-generates interactive API docs.

In this project: serves the HTML chat page at GET / and runs the full pipeline on POST /ask.

Uvicorn

Uvicorn is the ASGI server that runs FastAPI. Think of FastAPI as the engine of a car and Uvicorn as the chassis — Uvicorn handles the actual network connections, keeps the server alive, and passes requests to FastAPI to handle.

Requests (Python Library)

The requests library is how Python makes HTTP calls. Every call to the Gemini API in this project goes through requests.post(url, json=body). It's the same as what your browser does when it loads a webpage, but from Python code.

BeautifulSoup4

BeautifulSoup is a Python library for parsing HTML. When the scraper fetches a Stripe documentation page, the raw response is a string of HTML markup (<div>, <nav>, <p>, <script>, etc.). BeautifulSoup parses that string into a tree structure, allowing the scraper to remove navigation/footer elements and extract only the main documentation text.

Python-dotenv

python-dotenv reads the .env file and loads API keys into Python's environment variables. This prevents secrets from being hardcoded in the source code. The pattern is universal in production Python development.

Pydantic

Pydantic is a data validation library. FastAPI uses it to validate the incoming request body. When the browser sends {"question": "..."}, Pydantic checks that question is a string and not empty before the code even touches it. If validation fails, FastAPI automatically returns a 422 error with a clear message.

LangChain Core

Provides the ChatPromptTemplate class — a reusable prompt with named variable slots. Instead of using Python f-strings, prompt templates make it easy to define prompts once and fill variables in consistently. LangGraph also depends on langchain-core internally.

LangGraph

As explained in Section 7 — the graph-based pipeline orchestrator. It manages state passing between the 5 nodes, ensures they run in order, and handles the data flow between them.

Google Gen AI SDK (google-genai)

Google's Python SDK for the Gemini API. In this project it is a transitive dependency (installed because langchain-google-genai needs it) but not called directly. All direct Gemini calls use requests instead, giving full control over API version and endpoint routing.

Pinecone SDK

The official Python client for Pinecone. Used to create the index, upsert vectors, and run similarity queries. The SDK handles authentication, HTTP connection pooling, and retries to the Pinecone API.

13 · What Happens When You Ask a Question

Here is the complete, detailed journey of a single question through the entire system:

1
You type "How do I verify a Stripe webhook?" and press Enter. JavaScript's fetch() sends an HTTP POST request to http://localhost:8000/ask with body {"question": "How do I verify a Stripe webhook?"}
2
FastAPI receives the request. Pydantic validates the body. The ask() function calls run_pipeline(question).
3
LangGraph initialises the state as a Python dict: {"query": "How do I verify...", "context": "", "sources": [], "answer": "", ...} and starts execution at the "retrieve" node.
4
[RETRIEVE] Embedding API call #1. POST to generativelanguage.googleapis.com/.../gemini-embedding-001:embedContent with the question text. Gets back 3,072 floats in ~200ms.
5
[RETRIEVE] Pinecone query. Sends the 3,072-float vector to Pinecone asking for top 5 matches. Gets back 5 document chunks from Stripe docs in ~100ms.
6
[RETRIEVE] State updated: context = formatted string of 5 chunks with source URLs. sources = list of unique source pages.
7
[GENERATE] LLM call #1. POST to generativelanguage.googleapis.com/.../gemini-2.5-flash:generateContent with the 5 chunks as context + the user's question. Gemini reads the context and writes an answer. ~1–3 seconds.
8
[GENERATE] State updated: answer = the generated answer text.
9
[FACT CHECK] LLM call #2. POST to Gemini again, this time with a fact-checking prompt that includes the answer and the context. Temperature = 0. Gemini extracts claims and assigns verdicts. ~2–4 seconds.
10
[FACT CHECK] State updated: fact_check_result = JSON with claims, verdicts, overall PASS/FAIL.
11
[CONSISTENCY GUARD] LLM call #3. POST to Gemini with a consistency audit prompt that includes the answer, context, AND the Layer 1 verdicts. Temperature = 0. Gemini assigns hallucination score + label. ~2–4 seconds.
12
[COMPILE] Assemble. All outputs combined into final_output dict. LangGraph marks execution complete.
13
FastAPI returns JSON to the browser with answer, sources, claim verdicts, and trust score.
14
JavaScript renders the Trust Card — the answer bubble appears, the score bar animates from 0 to the final score, the trust badge turns green/amber/red based on the label, and expandable sections show per-claim verdicts and source links.
Total Time
A typical question takes 5–15 seconds end-to-end. Most of this time is the three sequential LLM calls (each 1–4 seconds). The embedding call and Pinecone search together take under 500ms. The typing indicator in the UI shows while this is happening.

14 · The Chat UI Explained

14.1 How It's Built

The entire frontend is a single HTML file (api/templates/index.html) with no external libraries, no React, no npm. Just HTML, CSS, and ~120 lines of vanilla JavaScript. FastAPI serves it with FileResponse — just streaming the file directly.

14.2 The Trust Card Components

14.3 The Score Animation

The animating score number is implemented with setInterval:

let current = 0;
const step = score / 50;   // reach target in 50 ticks
const iv = setInterval(() => {
    current = Math.min(current + step, score);
    numEl.textContent = Math.round(current);
    if (current >= score) clearInterval(iv);
}, 20);  // fires every 20ms = ~1 second total animation

The bar uses a CSS transition: transition: width 1.1s cubic-bezier(.22,1,.36,1) — an "ease out" curve that starts fast and slows at the end, giving a satisfying visual weight.

15 · Setup Guide

What You Need

  • Python 3.12 or higher
  • A Gemini API key — free from aistudio.google.com/app/apikey
  • A Pinecone API key — free Serverless tier from app.pinecone.io
  • Internet connection during ingestion and queries

Step 1 — Install Dependencies

cd truthguard
python3 -m venv venv
source venv/bin/activate       # Mac/Linux
# venv\Scripts\activate        # Windows
pip install -r requirements.txt

Step 2 — Configure API Keys

cp .env.example .env
# Edit .env — add your three values:
GEMINI_API_KEY=your_gemini_key_here
PINECONE_API_KEY=your_pinecone_key_here
PINECONE_INDEX_NAME=truthguard

Step 3 — Run Ingestion (Crawl Stripe Docs)

python3 ingestion/scrape_stripe.py

This will:

  • Auto-discover your available embedding model
  • Crawl up to 100 Stripe documentation pages
  • Embed each chunk and store it in Pinecone
  • Take 15–30 minutes (respects API rate limits)

Step 4 — Start the Server

uvicorn api.main:app --port 8000

On startup you should see:

  Embedding model: models/gemini-embedding-001
  LLM model:       models/gemini-2.5-flash
INFO:     Application startup complete.

Step 5 — Open the App

Go to http://localhost:8000 in your browser. Try asking:

  • "How do I create a PaymentIntent?"
  • "What events does Stripe send for failed payments?"
  • "How does Stripe Connect work?"
  • "How do I verify webhook signatures?"
Important
Always activate the virtual environment (source venv/bin/activate) before running any command. Run uvicorn without --reload — on macOS the reload subprocess can fail DNS lookups for external APIs.
API Key Security
Never commit .env to git. Never share API keys in chat messages, screenshots, or error logs. If a key is accidentally exposed, regenerate it immediately at the provider's dashboard.
